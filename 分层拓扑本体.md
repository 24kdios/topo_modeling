# 分层拓扑本体定义报告

## 3. 第1层：网络层（Network Layer）

### 3.1 层级概述

网络层是分层拓扑的最底层，定义物理网络设备和基础设施。本层实体描述网络节点、物理设备、端口、光纤等硬件资源。

**IETF标准参考**: RFC 8345 (Network Topology Data Model), RFC 8348 (Hardware Entity Data Model), RFC 7223 (Interfaces)

### 3.2 实体定义

### 3.3 层内关系定义

#### 3.3.1 单向关系

**Node → Rack**（节点包含机架）

```yaml
relationship-type: contains
source-entity: Node
target-entity: Rack
direction: unidirectional
layer-scope: intra-layer
semantics: 节点设备包含机架
usage-scenario: 查询设备上的机架布局
```

**Rack → Shelf**（机架包含子架）
```yaml
relationship-type: contains
source-entity: Rack
target-entity: Shelf
direction: unidirectional
layer-scope: intra-layer
semantics: 机架包含多个子架
usage-scenario: 查询机架内的子架
```

**Shelf → Board**（子架包含板卡）
```yaml
relationship-type: contains
source-entity: Shelf
target-entity: Board
direction: unidirectional
layer-scope: intra-layer
semantics: 子架包含多个板卡
usage-scenario: 查询子架上的板卡
```

**Board → PhysicalPort**（板卡包含物理端口）
```yaml
relationship-type: contains
source-entity: Board
target-entity: PhysicalPort
direction: unidirectional
layer-scope: intra-layer
semantics: 板卡提供多个物理端口
usage-scenario: 查询板卡上的端口
```

**PhysicalPort → OpticalModule**（端口包含光模块）
```yaml
relationship-type: contains
source-entity: PhysicalPort
target-entity: OpticalModule
direction: unidirectional
layer-scope: intra-layer
semantics: 光模块插入物理端口
usage-scenario: 查询端口上的光模块
```

**PhysicalPort ↔ OpticalFiber**（端口连接光纤）
```yaml
relationship-type: connects-to
source-entity: PhysicalPort
target-entity: OpticalFiber
direction: bidirectional
layer-scope: intra-layer
semantics: 物理端口通过光纤与其他端口连接
reverse-semantics: 光纤连接两个物理端口
usage-scenario: 查询端口间的光纤连接关系
```

**Node → PowerSupply**（节点包含电源模块）
```yaml
relationship-type: contains
source-entity: Node
target-entity: PowerSupply
direction: unidirectional
layer-scope: intra-layer
semantics: 节点设备包含电源模块
usage-scenario: 查询设备的电源配置
```

**Node → Fan**（节点包含风扇）
```yaml
relationship-type: contains
source-entity: Node
target-entity: Fan
direction: unidirectional
layer-scope: intra-layer
semantics: 节点设备包含风扇
usage-scenario: 查询设备的散热配置
```

#### 3.3.2 双向关系

**contains ↔ belongs-to**（包含关系）
```yaml
relationship-type: contains
source-entity: Network, Site, Node, Rack, Shelf, Board
target-entity: Node, Node, Rack, Shelf, Board, PhysicalPort
direction: bidirectional
reverse-relationship-type: belongs-to
layer-scope: intra-layer
semantics: 父实体包含子实体
reverse-semantics: 子实体属于父实体
usage-scenario: 自顶向下查询（contains）和自底向上查询（belongs-to）
```

**connects-to ↔ connected-by**（连接关系）
```yaml
relationship-type: connects-to
source-entity: PhysicalPort
target-entity: OpticalFiber
direction: bidirectional
reverse-relationship-type: connected-by
layer-scope: intra-layer
semantics: 端口连接光纤
reverse-semantics: 光纤连接端口
usage-scenario: 查询端口的光纤连接和光纤两端的端口
```

#### 3.3.3 层级关系

网络层实体存在明确的层级结构：

```
Network（网络域）
  ├── Site（站点）
  │     └── Node（节点）
  │           ├── Rack（机架）
  │           │     └── Shelf（子架）
  │           │           └── Board（板卡）
  │           │                 └── PhysicalPort（物理端口）
  │           │                       └── OpticalModule（光模块）
  │           ├── PowerSupply（电源模块）
  │           └── Fan（风扇）
  └── Node（节点）
        └── ...

PhysicalPort ←→ OpticalFiber（光纤连接）
```

### 3.4 核心短接关系

为优化高频查询性能，定义网络层核心短接关系：

**Node → PhysicalPort**（节点直达端口）
```yaml
relationship-type: has-port
source-entity: Node
target-entity: PhysicalPort
direction: unidirectional
layer-scope: intra-layer-shortcut
semantics: 节点直达所有物理端口（跳过Rack/Shelf/Board层级）
usage-scenario: 快速查询节点的所有端口（无需遍历层级）
optimization: 减少查询跳数，从3-4跳减少到1跳
```

**Node → OpticalModule**（节点直达光模块）
```yaml
relationship-type: has-module
source-entity: Node
target-entity: OpticalModule
direction: unidirectional
layer-scope: intra-layer-shortcut
semantics: 节点直达所有光模块
usage-scenario: 快速查询节点的所有光模块
optimization: 减少查询跳数
```

**Node → OpticalFiber**（节点直达光纤）
```yaml
relationship-type: connects-fiber
source-entity: Node
target-entity: OpticalFiber
direction: unidirectional
layer-scope: intra-layer-shortcut
semantics: 节点直达连接的光纤
usage-scenario: 快速查询节点间的光纤连接
optimization: 支持快速拓扑发现和故障定位
```

**Site → Node**（站点直达节点）
```yaml
relationship-type: has-node
source-entity: Site
target-entity: Node
direction: unidirectional
layer-scope: intra-layer-shortcut
semantics: 站点直达所有节点设备
usage-scenario: 快速查询站点内的所有设备
optimization: 站点级设备清单查询
```

**Site → PhysicalPort**（站点直达端口）
```yaml
relationship-type: has-port
source-entity: Site
target-entity: PhysicalPort
direction: unidirectional
layer-scope: intra-layer-shortcut
semantics: 站点直达所有物理端口
usage-scenario: 快速查询站点内的所有端口
optimization: 站点级端口清单查询
```

## 4. 第2层：链路层（Link Layer）

### 4.1 层级概述

链路层定义网络链路连接和逻辑链路实例。本层实体描述物理链路、链路聚合、VLAN、桥接域、逻辑接口等二层网络资源。

**IETF标准参考**: RFC 8345 (Network Topology Data Model), RFC 7223 (Interfaces), IEEE 802.1AX (Link Aggregation), IEEE 802.1Q (VLAN)

### 4.3 层内关系定义

#### 4.3.1 单向关系

**PhysicalPort → TerminationPoint**（端口提供终结点）
```yaml
relationship-type: provides
source-entity: PhysicalPort
target-entity: TerminationPoint
direction: unidirectional
layer-scope: intra-layer
semantics: 物理端口提供链路终结点
usage-scenario: 查询端口的终结点配置
```

**TerminationPoint → Link**（终结点连接链路）
```yaml
relationship-type: connects-to
source-entity: TerminationPoint
target-entity: Link
direction: unidirectional
layer-scope: intra-layer
semantics: 终结点连接到链路
usage-scenario: 查询终结点的链路连接
```

**PhysicalPort ↔ Link**（端口连接链路）
```yaml
relationship-type: connects-to
source-entity: PhysicalPort
target-entity: Link
direction: bidirectional
layer-scope: intra-layer
semantics: 物理端口连接链路
reverse-semantics: 链路连接物理端口
usage-scenario: 查询端口的链路连接和链路的端口
```

### 9.6 层间关系汇总表

| 层间关系 | 关系类型 | 自顶向下语义 | 自底向上语义 | 典型场景 |
|---------|---------|-------------|-------------|---------|
| **Business → Service** | uses ↔ serves | 业务服务使用网络服务 | 网络服务服务于业务服务 | 基站业务使用VPN回传 |
| **Service → Tunnel** | carried-by ↔ carries | 网络服务由隧道承载 | 隧道承载网络服务 | VPN由MPLS-TE隧道承载 |
| **Tunnel → Routing** | relies-on ↔ supports | 隧道依赖路由实例 | 路由实例支撑隧道 | TE隧道依赖VRF路由 |
| **Routing → Link** | uses-link ↔ carries-route | 路由使用链路转发 | 链路承载路由流量 | VRF使用链路转发 |
| **Link → Network** | connects ↔ provides-link | 链路连接节点 | 节点提供链路端点 | 链路连接两个节点 |

### 9.7 层间依赖链

自顶向下依赖链（从Business层到Network层）：

```
BusinessService（业务服务）
  └── uses → NetworkService（网络服务）
        └── carried-by → Tunnel（隧道）
              └── relies-on → RoutingInstance（路由实例）
                    └── uses-link → Link（链路）
                          └── connects → Node（网络节点）
                                └── contains → PhysicalPort（物理端口）
```

自底向上支撑链（从Network层到Business层）：

```
PhysicalPort（物理端口）
  └── terminates-link → Link（链路）
        └── carries-route → Route（路由）
              └── supports → Tunnel（隧道）
                    └── carries → VPNInstance（VPN实例）
                          └── serves → BusinessService（业务服务）
```
